### OAuth 2.0 `client_credentials` Authentication Flow
PayPal APIs use OAuth 2.0 Bearer tokens generated by exchanging your application's `client_id` and `client_secret`.

#### Endpoint
`POST https://api-m.sandbox.paypal.com/v1/oauth2/token`

#### Required Headers
* `Content-Type: application/x-www-form-urlencoded`
* `Accept: application/json`
* `Authorization: Basic <base64(client_id:client_secret)>`

#### Request Body
```
grant_type=client_credentials
```

#### Example cURL
```bash
curl -v -X POST "https://api-m.sandbox.paypal.com/v1/oauth2/token" \
  -u "PAYPAL_CLIENT_ID:PAYPAL_CLIENT_SECRET" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials"
```

#### Sample Response
```json
{
  "scope": "https://uri.paypal.com/services/invoicing https://uri.paypal.com/services/disputes/read-buyer ...",
  "access_token": "A21AAFExxxxxx...",
  "token_type": "Bearer",
  "app_id": "APP-80W284485P519543T",
  "expires_in": 31668,
  "nonce": "2026-10-31T12:00:00Z..."
}
```

#### Making Authenticated API Calls
Include the `access_token` in subsequent API requests via the `Authorization` header:
```http
Authorization: Bearer <access_token>
```
*Note: Tokens typically expire in ~8 hours (`expires_in` seconds). Clients should cache the token and automatically refresh it when nearing expiration.*

## 2. PayPal AI Agent Toolkit & MCP Integration

PayPal provides official developer tooling for AI coding agents and autonomous commerce workflows.

### A. Python Agent Toolkit (`paypal-agent-toolkit`)
```bash
pip install paypal-agent-toolkit
```

#### Initialization Pattern (LangChain / CrewAI / OpenAI Agents)
```python
import os
from paypal_agent_toolkit.shared.configuration import Configuration, Context
from paypal_agent_toolkit.langchain.toolkit import PayPalToolkit
# Or: from paypal_agent_toolkit.crewai.toolkit import PayPalToolkit
# Or: from paypal_agent_toolkit.openai.toolkit import PayPalToolkit

# 1. Define enabled tools and sandbox context
config = Configuration(
    actions={
        "orders": {"create": True, "get": True, "capture": True},
        "invoices": {"create": True, "list": True, "send": True, "cancel": True},
        "products": {"create": True, "list": True},
        "subscriptionPlans": {"create": True, "list": True, "show": True},
        "disputes": {"list": True, "get": True}
    },
    context=Context(sandbox=True)
)

# 2. Instantiate toolkit
toolkit = PayPalToolkit(
    client_id=os.getenv("PAYPAL_CLIENT_ID"),
    secret=os.getenv("PAYPAL_CLIENT_SECRET"),
    configuration=config
)

# 3. Retrieve callable tool definitions for LLMs
tools = toolkit.get_tools()
```

## 3. Core REST API Endpoints & Request Headers

### Essential Request Headers
Every REST request must include:
| Header | Description | Required? | Example |
| :--- | :--- | :---: | :--- |
| `Authorization` | Bearer token authentication | **Yes** | `Bearer A21AA...` |
| `Content-Type` | Payload format | **Yes (POST/PUT/PATCH)** | `application/json` |
| `Accept` | Expected response format | **Yes** | `application/json` |
| `PayPal-Request-Id` | Unique UUID for **API Idempotency** | **Recommended for POST** | `9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d` |
| `PayPal-Partner-Attribution-Id`| Partner Build Notation (BN) code | Optional | `BN-CODE-HERE` |

> **Idempotency (`PayPal-Request-Id`):**  
> On operations like order creation or payment captures, passing a unique UUID prevents duplicate charges if network drops or retries occur. PayPal stores the request ID for up to 45 days.

### Active REST API Endpoints

#### 1. Orders API (v2) — Checkout & Pay Later
* `POST /v2/checkout/orders` — Create an order.
  ```json
  {
    "intent": "CAPTURE",
    "purchase_units": [
      {
        "reference_id": "item_123",
        "description": "Sony A7 IV Camera",
        "amount": {
          "currency_code": "USD",
          "value": "750.00"
        }
      }
    ],
    "payment_source": {
      "paypal": {
        "experience_context": {
          "payment_method_preference": "IMMEDIATE_PAYMENT_REQUIRED",
          "brand_name": "AI Financial Agent",
          "locale": "en-US",
          "landing_page": "GUEST_CHECKOUT",
          "user_action": "PAY_NOW",
          "return_url": "https://example.com/return",
          "cancel_url": "https://example.com/cancel"
        }
      }
    }
  }
  ```
* `GET /v2/checkout/orders/{id}` — Retrieve order details and payment status.
* `POST /v2/checkout/orders/{id}/capture` — Capture authorized order funds.

#### 2. Invoicing API (v2) — Bill Creation & Sending
* `POST /v2/invoicing/generate-next-invoice-number` — Generate standard sequential invoice number.
* `POST /v2/invoicing/invoices` — Create a draft invoice.
  ```json
  {
    "detail": {
      "invoice_number": "INV-2026-001",
      "invoice_date": "2026-10-31",
      "currency_code": "USD",
      "note": "AI Financial Advisory Consultation & Setup"
    },
    "invoicer": {
      "name": { "given_name": "Merchant", "surname": "Store" },
      "email_address": "merchant@business.example.com"
    },
    "primary_recipients": [
      {
        "billing_info": {
          "email_address": "buyer@personal.example.com"
        }
      }
    ],
    "items": [
      {
        "name": "Financial Advisory Service",
        "quantity": "1",
        "unit_amount": {
          "currency_code": "USD",
          "value": "150.00"
        }
      }
    ]
  }
  ```
* `POST /v2/invoicing/invoices/{invoice_id}/send` — Email the invoice and generate payment link.
* `GET /v2/invoicing/invoices/{invoice_id}` — Check payment status of an invoice.

#### 3. Reporting & Transaction Search APIs (v1) — Account Analysis
* `GET /v1/reporting/balances?currency_code=USD` — Fetch available, ledger, and held balances.
* `GET /v1/reporting/transactions?start_date=2026-10-01T00:00:00Z&end_date=2026-10-31T23:59:59Z&fields=all` — Search recent settled and pending transaction records (dates, amounts, payer, fee, status).

#### 4. Payments API (v2)
* `POST /v2/payments/captures/{capture_id}/refund` — Refund an existing payment capture.
* `GET /v2/payments/captures/{capture_id}` — View capture details.

### HATEOAS Links & Dynamic Navigation
PayPal responses include a `links` array with contextual Hypermedia (HATEOAS) navigation:
```json
{
  "id": "5O190127TN364715T",
  "status": "CREATED",
  "links": [
    {
      "href": "https://api-m.sandbox.paypal.com/v2/checkout/orders/5O190127TN364715T",
      "rel": "self",
      "method": "GET"
    },
    {
      "href": "https://www.sandbox.paypal.com/checkoutnow?token=5O190127TN364715T",
      "rel": "payer-action",
      "method": "GET"
    },
    {
      "href": "https://api-m.sandbox.paypal.com/v2/checkout/orders/5O190127TN364715T/capture",
      "rel": "capture",
      "method": "POST"
    }
  ]
}
```
* **`rel: "payer-action"` (or `"approve"`):** Present this URL to the user to approve the checkout or Pay Later installment agreement.
* **`rel: "capture"`:** Execute this URL after user approval to complete transaction.

## 4. Deprecated APIs to Avoid

To ensure code complies with hackathon judging standards and current PayPal best practices, **do NOT use**:

| Deprecated / Legacy API | Modern Replacement | Reason for Deprecation |
| :--- | :--- | :--- |
| **NVP / SOAP APIs** | REST APIs (v2) | Legacy protocols; lack modern OAuth 2.0 and JSON support. |
| **Payments API v1** (`/v1/payments/payment`) | **Orders API v2** (`/v2/checkout/orders`) | v1 Payments does not support modern 3DS, SCA, or Pay Later flows. |
| **Invoicing API v1** (`/v1/invoicing/invoices`) | **Invoicing API v2** (`/v2/invoicing/invoices`) | v1 has rigid templates and lacks modern webhooks / real-time tracking. |
| **`checkout.js` (Legacy Frontend)** | **PayPal JS SDK (v6)** / `@paypal/paypal-js` | Older script lacks dynamic funding sources (Apple Pay, Venmo, Pay in 4). |
| **Adaptive Payments** | **PayPal Payouts REST API** / Multiparty Orders | Adaptive Payments is discontinued. |
